Android agent · 1.0.0

A Wazuh agent for phones that are not rooted.

A native Kotlin app. It enrolls with a Wazuh manager through wazuh-authd, then speaks the regular agent protocol to wazuh-remoted, so the phone shows up in the dashboard as a normal active agent.

Enrollment and the message codec live in protocol/. The phone app, collectors, and queue live in app/.

01

What the phone reports

Events are JSON with an android root object. The stock JSON decoder on the manager parses them. No custom decoder is required.

  1. Posture

    Screen lock, encryption, patch age, developer options, USB and wireless debugging, root and emulator indicators, verified boot, and device admin, accessibility, and notification-listener apps.

  2. Apps

    Installs, updates, and removals, with the installer, a sideload flag, and granted dangerous permissions. The first run after enrollment sends a full inventory.

  3. Network

    Changes in transport, VPN, addresses, DNS, and Wi-Fi security. The Wi-Fi name is included only if you grant location permission.

  4. Failed unlocks

    Each wrong PIN, pattern, or password, if you turn on the agent’s device admin. The manager alerts on 5 failures within 5 minutes. The admin only uses the watch-login policy. It cannot lock, wipe, or change the phone.

  5. Capabilities

    What this phone can and cannot see: device admin, Device Owner, location, and battery exemption. Sent with each posture report and shown in the app. The Status tab lists anything still missing under Needs attention.

  6. Owner logs

    On a Device Owner phone only: ADB shell commands, CA certificate installs, logging stopped, storage mounts, and DNS lookups and connections per app. Android delivers these logs in batches, often an hour or more apart.

  7. Agent log

    The app’s own errors and crashes.

02

Offline queue

Events wait in a local database while the phone is offline. The Events tab lists the last 500 events since the app started, whether each was sent yet, and the full JSON on tap. It has search, a filter per event type, and a pause button.

The phone keeps a regular agent session. When keepalives stop, the manager marks it disconnected and raises rule 504, after the manager’s disconnection time (10 minutes by default).

03

What it cannot see

Without root, the agent cannot read the system logcat, monitor system file integrity, or see other apps’ data. Security log and network log events need Device Owner mode, which needs a factory-reset phone. Failed unlocks are reported only while the agent’s device admin is on.

Remote upgrades (WPK) and remote configuration queries are not supported. A Device Owner phone can run a fixed set of containment commands from the manager. Some OEM builds kill background services even with the battery exemption. On those phones, also allow-list the app in the vendor’s battery settings.
